# Practice Labs and Applied Projects

## Purpose

Turn learning objectives into bounded exercises and reviewable artifacts. Each lab must identify its environment, inputs, expected output, evaluation criteria, and limitations.

## Lab format

- Lab ID and title
- Learning path and competency level
- Objective
- Prerequisites
- Environment and required tools
- Source material / starter data
- Tasks
- Expected artifacts
- Validation steps
- Assessment rubric
- Safety and data-handling notes
- Cleanup / reset instructions

## Starter labs

### LAB-CORE-001 — Map the AH-AIOS System

Produce a system map showing Core, AI Harness, WorldForge, and cross-cutting Human Stewardship. Identify interfaces and boundaries.

### LAB-CORE-002 — Trace a Governed Change

Use a sample change request to identify source, rationale, reviewer, approval state, version history, and verification evidence.

### LAB-HARNESS-001 — Specify a Tool Contract

Define a tool's purpose, input schema, output schema, permissions, failure modes, and test cases.

### LAB-HARNESS-002 — Evaluate a Workflow

Create a workflow with explicit steps, state transitions, human checkpoints, and success/failure tests.

### LAB-WF-001 — Build a Small Knowledge Model

Create a bounded world with entities, typed relationships, and validation rules.

### LAB-WF-002 — Establish Provenance

Register sources, formulate claims, attach evidence, label assessments, and inspect the resulting lineage.

### LAB-WF-003 — Review a Canon Change

Submit a change proposal, record reviewer rationale, handle a conflict case, and preserve prior versions.

### LAB-AH-001 — AFTER HUMANITY Continuity Case

Use an authorized story/world excerpt to map entities, chronology, relationships, and continuity constraints. Preserve the source text and label interpretation separately.

## Lab completion

A lab is complete only when the required artifacts are submitted and checked against its rubric. Merely opening a lab or following instructions does not establish competency.
