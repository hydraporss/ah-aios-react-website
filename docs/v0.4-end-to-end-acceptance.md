# WorldForge v0.4 — End-to-End Acceptance Record

**Disposition:** Implementation-complete for the reported code slice; browser-to-backend acceptance pending. This is not a full acceptance or production-readiness declaration.

## Scope and architecture boundary

WorldForge currently has two separate data paths:

- The main React prototype screens store their workspace in the browser profile. They do not synchronize with Django.
- The React **Server Governance** page calls the Django API for server workspaces, claims, evidence, proposals, decisions, reloads, and archive export. Django sessions and per-world membership roles govern those API operations.

The API provides session authentication and server-side authorization for its protected endpoints. This does not establish enterprise identity (such as SSO/MFA), a deployed production service, or production security controls. Django's HMAC audit chain is tamper-evident while the signing key remains protected; it is not immutable against an administrator who can change both database and key.

## Browser-to-backend acceptance

The Playwright acceptance script is present at `tests/e2e-governance.mjs` and drives the React page against a seeded Django database. Its scenarios cover anonymous/insufficient/authorized users, claim creation, original evidence capture, proposal review, reload, archive export, audit verification, and SQLite restore/round-trip comparison.

**Result: UNVERIFIED.** Edge could not be launched or controlled in the recorded environment, so the Playwright workflow did not complete. API tests and the existence of the script do not count as a browser pass.

## Audit and recovery

Django tests reported a signed audit-chain tamper check and a SQLite backup/restore round trip. Those results apply to the tested local backend and threat model. They do not establish immutable audit storage, PostgreSQL recovery, deployed backup operations, or archive-wide browser round-trip acceptance.

## Cleanup status

This is a local test-host cleanup issue, not a deployment artifact.

## Acceptance gate

Do not mark v0.4 fully accepted or production-ready until the reproducible React-to-Django browser workflow passes, with persisted state, server-determined authority, audit verification, and a successful archive-preserving restore. Separately document production identity, deployment configuration, and independent audit retention before making production governance claims.
